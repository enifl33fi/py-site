# T1. Сравнительный анализ генераторов статических сайтов

## Цель

Сравнить четыре генератора статических сайтов (SSG) на Python
применительно к задаче публикации результатов экспериментов
и выбрать оптимальный.

## Рассматриваемые генераторы

1. **MkDocs** с темой Material
2. **Sphinx** с MyST-Parser
3. **Pelican**
4. **Quarto** — как четвёртый, ориентированный на научный контент

## Обозначения

- ✅ — поддерживается из коробки
- ⚠ — через плагин / расширение / частично
- ❌ — только вручную или не поддерживается

## Веса критериев

Для задачи публикации результатов экспериментов веса выбраны так:

| Группа | Вес | Обоснование |
|---|---|---|
| Научный контент | 40% | Ключевое: формулы, ссылки на них, рисунки, таблицы, библиография, исполняемые ноутбуки |
| Вёрстка и шаблоны | 20% | Колонки, карточки, свои шаблоны, экспорт в PDF |
| Эксплуатация | 25% | CI/CD, версионирование, поиск, i18n, автодок |
| Экосистема | 15% | Зрелость, лицензия, активность, доступность через зеркала |

Научный контент весит больше остального: результат эксперимента публикуется ради формул, графиков и таблиц, а не ради красоты верстки.

## Вывод

**Оптимальный генератор: MkDocs + Material.**

Основания:

- простой Markdown, низкий порог входа;
- быстрая сборка, удобно для CI;
- хорошая интеграция с GitHub Actions и российскими CI/CD;
- легко деплоится как на GitHub Pages, так и на Helios по SSH/rsync;
- есть `mike` для версионирования, `mkdocstrings` для автодока;
- локальный поиск на русском работает «из коробки»;
- через плагины закрываются формулы (`pymdownx.arithmatex`), библиография (`mkdocs-bibtex`), ноутбуки (`mkdocs-jupyter`).

### Когда вывод меняется

- **Sphinx + MyST** — если публикуется код эксперимента и нужен полноценный autodoc из docstrings, сквозная нумерация, `numfig`, `intersphinx`.
- **Quarto** — если основной источник — Jupyter-ноутбуки и нужен экспорт в PDF/LaTeX и интерактивные графики «из коробки».
- **Pelican** — если задача ближе к блогу, чем к научной публикации.

## Аргументация в пользу выбора для P4

Для практического задания P4 (развёртывание на Helios с healthcheck, preview и откатом) MkDocs Material даёт минимум трения:

- сборка одной командой `mkdocs build --strict`;
- артефакт — каталог `site/`, легко кладётся и в GitHub Pages, и на сервер по rsync;
- поддержка базового URL через `site_url`, что критично при размещении в подкаталоге;
- локальный поиск, формулы и подсветка кода не требуют тяжёлых зависимостей.
